1. 프로젝트 개요

AURIX TC237 보드 2대를 CAN 버스로 연결하여 ADC 측정값을 실시간으로 전송하는 시스템을 구현한다.
Main 보드는 ADC AN0 채널을 10ms 주기로 샘플링 후 CAN으로 전송하고, Sub 보드는 이를 수신하여 UART로 PC에 출력한다.

4. 핵심 코드

4-1. Main 보드 — CAN 송신 (DrvCan.c)

void DrvCan_Init(void)
{
    IfxMultican_Can_Config canCfg;
    IfxMultican_Can_initModuleConfig(&canCfg, &MODULE_CAN);
    IfxMultican_Can_initModule(&s_can, &canCfg);

    IfxMultican_Can_NodeConfig nodeCfg;
    IfxMultican_Can_Node_initConfig(&nodeCfg, &s_can);
    nodeCfg.nodeId    = IfxMultican_NodeId_0;
    nodeCfg.baudrate  = 500000u;             /* 500 kbps */
    nodeCfg.rxPin     = &IfxMultican_RXD0B_P20_7_IN;
    nodeCfg.txPin     = &IfxMultican_TXD0_P20_8_OUT;
    IfxMultican_Can_Node_init(&s_node, &nodeCfg);

    IfxMultican_Can_MsgObjConfig txCfg;
    IfxMultican_Can_MsgObj_initConfig(&txCfg, &s_node);
    txCfg.msgObjId           = 0u;
    txCfg.messageId          = 0x100u;
    txCfg.frame              = IfxMultican_Frame_transmit;
    txCfg.control.messageLen = IfxMultican_DataLengthCode_2;
    IfxMultican_Can_MsgObj_init(&s_txMsgObj, &txCfg);
}

void DrvCan_SendUint16(uint16 value)
{
    IfxMultican_Message txMsg;
    IfxMultican_Message_init(&txMsg, 0x100u, (uint32)value, 0u,
                             IfxMultican_DataLengthCode_2);
    uint32 retry = 0u;
    while ((IfxMultican_Can_MsgObj_sendMessage(&s_txMsgObj, &txMsg)
            == IfxMultican_Status_notSentBusy) && (++retry < 10000u)) {}
}

4-2. Sub 보드 — CAN 수신 ISR (DrvCan.c)

IFX_INTERRUPT(DrvCan_RxISR, 0, DRVCAN_RX_PRIORITY)
{
    IfxMultican_Message rxMsg;
    IfxMultican_Can_MsgObj_readMessage(&s_rxMsgObj, &rxMsg);
    s_rxData = (uint16)(rxMsg.data[0] & 0x0FFFu);  /* 12-bit ADC */
    s_rxFlag = TRUE;
}

boolean DrvCan_ReceiveUint16(uint16 *value)
{
    if (!s_rxFlag) return FALSE;
    s_rxFlag = FALSE;
    *value = s_rxData;
    return TRUE;
}

4-3. Sub 보드 — GTM Timer (DrvGtmTimer.c)

void DrvGtmTimer_Init(void)
{
    Ifx_GTM *gtm  = &MODULE_GTM;
    float32  fMod = IfxGtm_Cmu_getModuleFrequency(gtm);

    IfxGtm_enable(gtm);
    IfxGtm_Cmu_setGclkFrequency(gtm, fMod);
    IfxGtm_Cmu_enableClocks(gtm, IFXGTM_CMU_CLKEN_FXCLK);  /* ← 필수 */

    IfxGtm_Tom_Pwm_Config cfg;
    IfxGtm_Tom_Pwm_initConfig(&cfg, gtm);
    cfg.tom                   = IfxGtm_Tom_0;
    cfg.tomChannel            = IfxGtm_Tom_Ch_1;
    cfg.clock                 = IfxGtm_Tom_Ch_ClkSrc_cmuFxclk1;
    cfg.period                = 6250u;   /* FXCLK1=6.25MHz → 1ms */
    cfg.interrupt.ccu0Enabled = TRUE;
    cfg.interrupt.isrPriority = DRVGTMTIMER_ISR_PRIORITY;
    IfxGtm_Tom_Pwm_init(&s_timer, &cfg);
}

4-4. Sub 보드 — 스케줄러 (Scheduler.c)

void Scheduler_Run(void)
{
    static uint32 last_counter = 0u;
    uint32 now = g_1ms_counter;

    if (now == last_counter) return;
    last_counter = now;

    if ((now %   1U) == 0U) AppTask_1ms();
    if ((now %  10U) == 0U) AppTask_10ms();
    if ((now % 100U) == 0U) AppTask_100ms();
}

5. 트러블슈팅 — GTM ISR 미동작

[현상] Sub 보드에서 GTM TOM0 Ch1 ISR이 진입되지 않음 → g_1ms_counter 증가 안됨 → Scheduler 동작 불가
항목내용
원인IfxGtm_Cmu_enableClocks(gtm, IFXGTM_CMU_CLKEN_FXCLK) 미호출 → FXCLK1 소스 클럭 비활성화 상태
Main 프로젝트DrvPwm_Init() 내부에서 위 함수 호출 → 의존성 존재
Sub 프로젝트DrvPwm 없음 → FXCLK 미활성화 → TOM Ch1 타이머 동작 불가
수정DrvGtmTimer_Init() 내부에서 직접 IfxGtm_Cmu_enableClocks() 호출

GTM 클럭 체인

fSOURCE (200 MHz)
  └─ GTM Module Freq = fSOURCE / 2 = 100 MHz
      └─ GCLK = GTM Module Freq = 100 MHz
          └─ FXCLK1 = GCLK / 16 = 6,250,000 Hz
              └─ period = 6,250 ticks = 1 ms ← ISR 주기

7. 데이터 흐름 요약

[Main 보드 — 10ms마다]
AN0 핀 전압 (0~3.3V)
  → ADC 12bit 변환 (0~4095)
  → DrvCan_SendUint16(value)
  → CAN Frame: ID=0x100, DLC=2, data[0]=(uint32)value
  → P20.8 → TLE7250G → CANH/CANL → 버스

[Sub 보드 — 수신 즉시]
CANH/CANL → TLE7250G → P20.7
  → CAN RX ISR (DrvCan_RxISR)
  → rxMsg.data[0] & 0x0FFF → s_rxData
  → AppTask_10ms(): DrvCan_ReceiveUint16() → DrvUart_SendUint16()
  → UART: "XXXX\n" (ASCII 10진수)
  → P15.2 → USB-TTL → PC 시리얼 터미널
