TC237 PWM 설계 요약

1. 사용 모듈

항목내용
MCUInfineon AURIX TC237
PWM 모듈GTM (General Timer Module) — TOM0 Channel 0
출력 핀P00.9 (TOUT18, IfxGtm_TOM0_0_TOUT18_P00_9_OUT)
iLLD APIIfxGtm_Tom_Pwm

2. 클럭 체인 (100 Hz 도출 과정)

fSYS = 200 MHz
  └─ GTM GCLK = 200 MHz        (IfxGtm_Cmu_setGclkFrequency)
       └─ FXCLK2 = ÷ 256       (IfxGtm_Tom_Ch_ClkSrc_cmuFxclk2)
            = 781,250 Hz
               └─ period = 7,812 ticks
                    = 781,250 ÷ 7,812 = 100.006 Hz  ✓  (오차 0.006%)

TOM은 16-bit 카운터이므로 FXCLK0(200 MHz) ~ FXCLK1(12.5 MHz)은 ticks 값이 65,535를 초과합니다.
따라서 FXCLK2 (÷256, 781,250 Hz) 를 선택하여 7,812 ticks로 100 Hz를 구현합니다.

3. PWM 동작 원리

카운터: 0 ──────── CM1 ────────────── CM0(=7,812) ─→ 리셋 ──→ ...
출력:   HIGH ──────┘ LOW ─────────────────────────────┘ HIGH ...
레지스터값역할
CM0 (period register)7,812 ticksPWM 주기 결정
CM1 (duty register)duty% × 7,812 / 100HIGH 구간 결정

Duty 해상도 : 7,812 단계 (약 0.013% / step)

4. Duty 가변 설계

ADC Ch0 (P40.0)         AppTask_10ms (10 ms 주기)         GTM TOM0 Ch0
  12-bit (0~4095)  ──→  dutyPct = adcVal × 100 / 4095  ──→  SetDuty() 호출
                                                              │
                                                       shadow register 기록
                                                       + TGC trigger
                                                       (다음 주기 경계에서 적용)
  • P40.0에 연결된 가변저항(또는 외부 전압)으로 duty를 실시간 조절
  • Shadow register 방식 → 현재 주기 완료 후 적용되므로 글리치(glitch) 없음

5. 소프트웨어 구조

Cpu0_Main.c
  └─ DrvPwm_Init()           ← GTM 클럭 설정 + TOM 채널 초기화 (초기 Duty 50%)

Scheduler (1 ms tick)
  └─ AppTask_10ms()
       ├─ DrvAdc_Run()         ← ADC Ch0~Ch2 스캔 (10 ms 주기)
       └─ DrvPwm_SetDuty()     ← ADC Ch0 결과 → duty 변환 및 적용

6. 파일 구성

파일구분역할
DrvPwm.c신규GTM 초기화, 클럭 설정, duty 업데이트 구현
DrvPwm.h신규DrvPwm_Init() / DrvPwm_SetDuty() API 선언
Cpu0_Main.c수정DrvPwm_Init() 호출 추가
AppTask.c수정ADC → duty 변환 로직 추가 (10 ms Task)
참고 : DrvStm (STM 기반 1 ms 스케줄러)은 GTM과 독립된 클럭을 사용하므로 GTM GCLK 설정 변경에 영향을 받지 않습니다.
