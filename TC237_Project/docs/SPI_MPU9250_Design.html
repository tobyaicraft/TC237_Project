1. 시스템 개요

본 설계는 TC237 마이크로컨트롤러의 QSPI3 모듈을 SPI Master로 구성하여, MPU-9250 9축 IMU 센서(가속도계 3축 + 자이로스코프 3축 + 자력계 3축)와 통신하는 시스템이다. 가속도계와 자이로스코프 데이터를 100Hz 주기로 읽어 Complementary Filter를 적용하여 Roll/Pitch/Yaw 자세 각도를 계산한다.

2. SPI 통신 규격 결정

MPU-9250은 I2C와 SPI 두 가지 인터페이스를 지원한다. 본 설계에서 SPI를 선택한 이유는 다음과 같다.

비교 항목I2CSPI
최대 속도400 kHz (Fast Mode)20 MHz (센서 데이터 읽기)
신호선 수2 (SDA, SCL)4 (SCLK, MOSI, MISO, CS)
Full Duplex불가가능
TC237 지원I2C 모듈 또는 ASCLINQSPI 전용 모듈

TC237의 QSPI 모듈은 SPI 통신에 최적화된 전용 하드웨어이며, DMA 지원, 인터럽트 기반 전송, 하드웨어 FIFO를 제공한다. I2C 대비 50배 빠른 클럭을 사용할 수 있어 SPI를 선택하였다.

3. CPOL / CPHA 설정 근거

3.1 SPI 모드란?

SPI 통신의 클럭 동작은 CPOL(Clock Polarity)과 CPHA(Clock Phase) 두 파라미터로 결정된다.

SPI ModeCPOLCPHA클럭 Idle데이터 샘플링
Mode 000LowRising Edge (첫 번째 에지)
Mode 101LowFalling Edge (두 번째 에지)
Mode 210HighFalling Edge (첫 번째 에지)
Mode 311HighRising Edge (두 번째 에지)

3.2 MPU-9250 데이터시트 요구사항

MPU-9250 Product Specification (PS-MPU-9250A-01) Section 7.5에 따르면:

MPU-9250 SPI Interface:
• Supports SPI Mode 0 (CPOL=0, CPHA=0) and Mode 3 (CPOL=1, CPHA=1)
• Data is sampled on the rising edge of SCLK
• Data is output on the falling edge of SCLK
• MSB first, 8-bit frame

Mode 0과 Mode 3 모두 rising edge에서 데이터를 샘플링하는 공통점이 있다. 본 설계에서는 가장 기본적인 Mode 0 (CPOL=0, CPHA=0)을 선택하였다.

3.3 TC237 QSPI 설정 코드

/* TC237 QSPI3 채널 설정 */
chCfg.ch.mode.clockPolarity  = 0;   /* CPOL=0: 클럭 Idle = Low   */
chCfg.ch.mode.shiftClock     = 1;   /* 데이터 Shift = Trailing Edge (Falling) */
chCfg.ch.mode.dataHeading    = 1;   /* MSB first                  */
chCfg.ch.mode.dataWidth      = 8;   /* 8-bit 프레임              */
주의 — TC237 QSPI의 shiftClock 파라미터:
TC237 QSPI에서 shiftClock은 데이터를 출력(Shift)하는 에지를 지정한다. shiftClock=1이면 trailing edge(falling)에서 데이터를 출력하고, 상대방(MPU-9250)은 leading edge(rising)에서 샘플링한다. 이는 SPI Mode 0 (CPHA=0)에 해당한다. 일반적인 CPHA 정의와 직접 매핑되지 않으므로 주의가 필요하다.

4.2 설계 결정: 1 MHz 고정

센서 데이터 영역(0x3B~0x48)은 20 MHz까지 가능하지만, 본 설계에서는 1 MHz로 통일하였다.

  • 안정성 우선: 점퍼선(약 10cm) 연결 환경에서 고주파는 신호 무결성 문제 발생 가능
  • 충분한 성능: 6축 12바이트를 1 MHz로 읽는 데 약 150μs. 10ms(100Hz) 주기 대비 1.5%에 불과
  • 단일 클럭: 레지스터 R/W와 데이터 읽기를 같은 속도로 통일하여 코드 단순화

6. SPI 프로토콜 (Read / Write 프레임)

6.1 프레임 구조

MPU-9250의 SPI 프레임은 첫 바이트의 MSB(bit 7)로 Read/Write를 구분한다.

Bit 7Bit 6~0동작
1레지스터 주소Read (0x80 | addr)
0레지스터 주소Write (0x00 | addr)

6.2 단일 레지스터 읽기

/*
 * SPI Read 타이밍:
 *
 * CS   ‾‾\_________________________________/‾‾
 * MOSI   [1|addr(7bit)] [  0x00 (dummy)   ]
 * MISO   [  (무시)     ] [  데이터(8bit)   ]
 * SCLK   _/‾\_/‾\_/‾\_/‾\_/‾\_/‾\_/‾\_/‾\_
 *          8 clocks        8 clocks
 */
uint8 DrvSpi_ReadReg(uint8 regAddr)
{
    uint8 txBuf[2];
    uint8 rxBuf[2];

    txBuf[0] = 0x80u | regAddr;   /* bit7=1: Read */
    txBuf[1] = 0x00u;              /* dummy byte   */

    DrvSpi_CsLow();
    DrvSpi_WaitReady();
    IfxQspi_SpiMaster_exchange(&s_spiChannel, txBuf, rxBuf, 2);
    DrvSpi_WaitReady();
    DrvSpi_CsHigh();

    return rxBuf[1];   /* 두 번째 바이트가 실제 데이터 */
}

6.3 단일 레지스터 쓰기

/*
 * SPI Write 타이밍:
 *
 * CS   ‾‾\_________________________________/‾‾
 * MOSI   [0|addr(7bit)] [  데이터(8bit)    ]
 * MISO   [     (무시)                      ]
 * SCLK   _/‾\_/‾\_/‾\_/‾\_/‾\_/‾\_/‾\_/‾\_
 *          8 clocks        8 clocks
 */
void DrvSpi_WriteReg(uint8 regAddr, uint8 data)
{
    uint8 txBuf[2];

    txBuf[0] = regAddr & 0x7Fu;   /* bit7=0: Write */
    txBuf[1] = data;

    DrvSpi_CsLow();
    DrvSpi_WaitReady();
    IfxQspi_SpiMaster_exchange(&s_spiChannel, txBuf, NULL_PTR, 2);
    DrvSpi_WaitReady();
    DrvSpi_CsHigh();
}

7. QSPI3 FIFO 한계와 대응

7.1 문제 현상

MPU-9250의 센서 데이터는 0x3B~0x48 영역에 14바이트(가속도 6 + 온도 2 + 자이로 6)가 연속으로 배치되어 있다. 이를 한 번의 SPI 트랜잭션으로 읽으려 하면(15바이트 = 주소 1 + 데이터 14), 앞쪽 4바이트만 정상 수신되고 나머지는 0으로 읽히는 현상이 발생하였다.

7.2 원인 분석

TC237의 QSPI3는 "경량(Light)" SPI 모듈로, QSPI0/1/2 대비 FIFO 크기가 작다. 8-bit 프레임 모드에서 RX FIFO가 수용할 수 있는 바이트 수를 초과하면 뒤쪽 데이터가 유실된다.

시도전송 크기결과
14바이트 버스트15 bytes (1+14)AX, AY만 정상, AZ~GZ = 0
6바이트 버스트 × 27 bytes (1+6)AX, AY만 정상, AZ = 0
2바이트 버스트 × 63 bytes (1+2)6축 전부 정상

7.3 해결: 축별 2바이트 분할 읽기

/* 각 축 2바이트씩 개별 읽기 (QSPI3 FIFO 한계 대응) */
DrvSpi_ReadBurst(0x3B, &buf[0],  2);   /* AX High, Low */
DrvSpi_ReadBurst(0x3D, &buf[2],  2);   /* AY High, Low */
DrvSpi_ReadBurst(0x3F, &buf[4],  2);   /* AZ High, Low */
buf[6] = 0; buf[7] = 0;              /* TEMP 생략    */
DrvSpi_ReadBurst(0x43, &buf[8],  2);   /* GX High, Low */
DrvSpi_ReadBurst(0x45, &buf[10], 2);   /* GY High, Low */
DrvSpi_ReadBurst(0x47, &buf[12], 2);   /* GZ High, Low */

각 트랜잭션이 3바이트(주소 1 + 데이터 2)로 FIFO 한계 내에서 동작하므로, 6축 모든 데이터를 안정적으로 수신할 수 있다.

8. 레지스터 쓰기 검증 (Write-Verify)

8.1 문제 현상

초기화 과정에서 레지스터에 값을 쓴 후 읽어보면 의도한 값과 다른 값이 저장되어 있었다.

레지스터쓴 값읽힌 값영향
PWR_MGMT_1 (0x6B)0x010x1BGYRO_STANDBY=1 → 자이로 비활성
PWR_MGMT_2 (0x6C)0x000x08DISABLE_ZA=1 → Z축 가속도 비활성
GYRO_CONFIG (0x1B)0x080x00±250°/s (기본값) 유지
ACCEL_CONFIG (0x1C)0x080x00±2g (기본값) 유지

8.2 원인

리셋 직후 또는 클럭 소스 변경 직후 내부 상태 전환 시간이 필요하며, 이 기간에 SPI 쓰기가 무시되거나 잘못 반영될 수 있다.

8.3 해결: Write-Read-Verify 패턴

static boolean writeRegVerify(uint8 regAddr, uint8 data)
{
    uint8 retry;
    uint8 readBack;

    for (retry = 0; retry < 5; retry++)
    {
        DrvSpi_WriteReg(regAddr, data);
        delay_ms(5);                       /* 반영 대기 */
        readBack = DrvSpi_ReadReg(regAddr);
        if (readBack == data)
        {
            return TRUE;                   /* 검증 성공 */
        }
    }
    return FALSE;                          /* 5회 실패 */
}

각 레지스터를 쓴 후 5ms 대기 → 읽기 → 비교하여 최대 5회 재시도한다. 이 방식으로 모든 레지스터가 의도한 값으로 설정됨을 보장한다.

10. 데이터 읽기 전략

10.1 레지스터 맵

센서 데이터는 0x3B부터 14바이트가 Big Endian(High byte first)으로 연속 배치되어 있다.

주소레지스터데이터

0x41, 0x42TEMP_OUT_H/L온도 (사용 안 함)

12. 자세 계산 (Complementary Filter)

12.1 축 매핑 (실측 기반)

MPU-9250 보드의 축 인쇄와 실제 동작을 대조하여 매핑을 결정하였다. 보드의 Y축 = 전진 방향(코), X축 = 날개 방향으로 장착한다.

물리 동작가속도 축자이로 축부호
Roll (날개 기울임)AX, AZGY (raw[1])반전 (-)
Pitch (기수 상하)AY, AZGX (raw[0])반전 (-)
Yaw (좌우 회전)-GZ (raw[2])정방향

12.2 Complementary Filter 원리

가속도계는 저주파 정확(중력 기반)하지만 진동에 취약하고, 자이로스코프는 고주파 정확(각속도 적분)하지만 드리프트가 누적된다. Complementary Filter는 두 센서의 장점을 결합한다. 

/* α = 0.96, DT = 0.01s (100Hz) */

/* 가속도계 기반 각도 (저주파) */
rollAcc  = atan2(-AX, AZ)
pitchAcc = atan2(AY, sqrt(AX² + AZ²))

/* Complementary Filter */
Roll  = α × (Roll  + gyroRate × dt) + (1-α) × rollAcc
Pitch = α × (Pitch + gyroRate × dt) + (1-α) × pitchAcc

/* Yaw: 자이로 적분 only (가속도 보정 불가) */
Yaw += yawRate × dt
α = 0.96의 의미:
자이로(고주파)에 96% 가중, 가속도(저주파)에 4% 가중. 시정수(time constant) = DT / (1-α) = 0.01 / 0.04 = 0.25초. 약 0.25초 이상의 느린 변화는 가속도계가 보정하고, 그보다 빠른 변화는 자이로가 추적한다.

12.3 캘리브레이션

시작 후 1초간(100회) 정지 상태에서 평균값을 수집하여 오프셋을 보정한다.

보정 대상방법목적
가속도 Roll/Pitch 오프셋100회 평균 후 차감초기 자세 = 0°,0° 기준
자이로 X/Y/Z 바이어스100회 평균 후 차감정지 시 각속도 ≈ 0°/s

12.4 Yaw 드리프트 억제

Yaw는 가속도계로 보정할 수 없으므로(중력은 수직 방향만 감지), 자이로 적분만으로 계산한다. 드리프트를 줄이기 위해 두 가지 기법을 적용하였다. 

#define YAW_DEADZONE  1.5f    /* ±1.5°/s 이하 무시 */
#define YAW_DECAY     0.998f  /* 정지 시 감쇠 계수 */

if (|yawRate| > YAW_DEADZONE)
    Yaw += yawRate × dt;      /* 회전 중 → 정상 적분 */
else
    Yaw ×= YAW_DECAY;          /* 정지 중 → 서서히 0 복귀 */
