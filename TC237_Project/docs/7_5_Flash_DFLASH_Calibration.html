7.5 AI와 함께하는 TC237 Flash 실습

이번 절에서는 DFLASH를 이용한 캘리브레이션 데이터 저장/복원 기능을 구현합니다. 인피니언 ILLD의 Flash API를 직접 사용하되, 실제 현업에서 쓰이는 패턴 — 매직넘버 검증, UART 명령 인터페이스, 부팅 시 자동 복원 — 을 조합하여 실용적인 드라이버를 만듭니다.

Claude Code에게 아래와 같이 요청합니다.

"DFLASH에 PWM Duty 값을 저장하고, 전원을 꺼도 유지되도록 캘리브레이션 드라이버를 만들어줘. UART로 D=75, SAVE, LOAD, CAL? 명령을 보내서 제어할 수 있게 해줘."

PFLASH vs DFLASH — 왜 DFLASH를 선택하는가

TC237에는 두 종류의 Flash가 있습니다. 코드가 실행되는 PFLASH(Program Flash)와 데이터 저장 전용인 DFLASH(Data Flash)입니다.

항목PFLASH (PF0)DFLASH (DF0)
용도프로그램 코드 저장데이터 저장 (캘리브레이션, 설정값)
시작 주소0xA00000000xAF000000
Page 크기32 Bytes8 Bytes
Erase 단위16 KB Sector8 KB Sector
Write 중 코드 실행같은 뱅크에서 실행 불가 (PSPR 복사 필요)별도 뱅크이므로 안전
Erase 수명~10만 회~10만 회

캘리브레이션 데이터를 저장할 때는 DFLASH가 적합합니다. 코드가 실행되는 PFLASH와 물리적으로 분리되어 있으므로, Write 중에도 프로그램이 정상 동작합니다. PFLASH에 쓰려면 함수를 PSPR(RAM)에 복사해야 하지만, DFLASH는 그런 작업이 필요 없습니다. iLLD의 Flash API를 직접 호출하면 됩니다.

데이터 구조체 설계 — 매직넘버 패턴

Flash에 저장할 데이터를 구조체로 정의합니다. DFLASH의 최소 Write 단위인 8바이트에 맞춰 설계합니다. 

typedef struct
{
    uint8  pwmDuty;      /* PWM Duty 0~100 [%]           (1 byte)  */
    uint8  reserved1;    /* 예약 (확장용)                (1 byte)  */
    uint16 reserved2;    /* 예약 (확장용)                (2 bytes) */
    uint32 magic;        /* 유효성 검증 매직넘버          (4 bytes) */
} DrvFlash_CalData;      /* 총 8 bytes = 1 DFLASH page             */

#define DRVFLASH_CAL_MAGIC  0xCAFE1234u

여기서 핵심은 magic 필드입니다. Flash는 Erase 직후 전부 0x00(DFLASH) 상태입니다. pwmDuty가 0이라면, 그것이 "사용자가 0%로 저장한 것"인지 "한 번도 저장한 적 없는 빈 Flash"인지 구분할 수 없습니다. 매직넘버 0xCAFE1234가 함께 기록되어 있으면 유효한 데이터로 인정하고, 아니면 무시합니다.

메모리 배치 (리틀엔디안)

구조체가 Flash에 기록되면 아래와 같이 배치됩니다. TriCore는 리틀엔디안이므로 바이트 순서에 주의합니다.

Offset+0+1+2+3+4+5+6+7
필드 pwmDutyreserved1reserved2 magic (리틀엔디안)
Duty=75 4B000000 3412FECA
Duty=80 50000000 3412FECA
Erase 상태 00000000 00000000

디버거 Memory 창에서 0xAF000000을 Hex로 보면, Duty=75일 때 4B000000 3412FECA로 표시됩니다. 0x4B = 십진수 75, 3412FECA는 리틀엔디안으로 읽으면 0xCAFE1234입니다.

Flash Write — DrvFlash_SaveCalibration 코드 분석

Flash에 데이터를 쓰는 전체 과정을 코드와 함께 살펴봅니다. DFLASH는 코드 실행 영역과 분리되어 있으므로 PFLASH처럼 PSPR 복사가 필요 없고, iLLD API를 직접 호출하면 됩니다. 

boolean DrvFlash_SaveCalibration(void)
{
    /* ① 저장할 데이터 준비 — 구조체를 두 개의 32-bit 워드로 분리 */
    DrvFlash_CalData cal;
    cal.pwmDuty   = g_pwmDuty;
    cal.reserved1 = 0u;
    cal.reserved2 = 0u;
    cal.magic     = DRVFLASH_CAL_MAGIC;     /* 0xCAFE1234 */

    uint32 wordL = *((uint32 *)&cal);       /* 하위 4바이트: [4B][00][00][00] */
    uint32 wordU = *((uint32 *)&cal + 1);   /* 상위 4바이트: [34][12][FE][CA] */

IfxFlash_loadPage2X32는 32-bit 워드 두 개(총 8바이트)를 받습니다. 구조체 8바이트를 하위/상위 워드로 쪼개서 전달합니다. 

    /* ② Endinit 해제 — Flash 레지스터 접근 보호 해제 */
    uint16 endinitPw = IfxScuWdt_getCpuWatchdogPassword();
    IfxScuWdt_clearCpuEndinit(endinitPw);

TC237은 안전장치로 Endinit 비트가 설정되어 있으면 Flash 제어 레지스터에 접근할 수 없습니다. Flash 조작 전에 반드시 해제하고, 완료 후 복원해야 합니다. 

    /* ③ 상태 클리어 */
    IfxFlash_clearStatus(0);

    /* ④ Sector 0 Erase — 8KB 전체가 지워짐 */
    IfxFlash_eraseSector(CAL_FLASH_ADDR);       /* 0xAF000000 */
    IfxFlash_waitUnbusy(0, IfxFlash_FlashType_D0);

Flash는 0→1로 비트를 바꿀 수 없습니다. 이미 데이터가 있는 곳에 덮어쓰려면 먼저 Erase로 전체를 0x00으로 초기화해야 합니다. DFLASH Sector 0은 8KB(0xAF000000~0xAF001FFF) 전체가 한 번에 지워집니다. waitUnbusy로 Erase 하드웨어 동작이 끝날 때까지 대기합니다. 

    /* ⑤ Page Mode 진입 → 데이터 로드 → Page Write */
    IfxFlash_enterPageMode(CAL_FLASH_ADDR);
    IfxFlash_loadPage2X32(CAL_FLASH_ADDR, wordL, wordU);
    IfxFlash_writePage(CAL_FLASH_ADDR);
    IfxFlash_waitUnbusy(0, IfxFlash_FlashType_D0);

이 세 단계가 실제 데이터를 쓰는 핵심입니다.

API동작
enterPageModeFlash 컨트롤러를 Page Programming 모드로 전환
loadPage2X32Assembly Buffer에 8바이트 데이터 적재 (DFLASH 1 Page = 8 Bytes)
writePageAssembly Buffer 내용을 실제 Flash 셀에 확정 기록
PFLASH와의 차이: PFLASH는 1 Page = 32바이트이므로 loadPage2X32를 4번 호출해서 버퍼를 채워야 합니다. DFLASH는 1 Page = 8바이트이므로 loadPage2X32 한 번이면 됩니다. 32바이트 배수 맞춤이나 나머지 바이트 처리도 필요 없어서 훨씬 간단합니다. 
    /* ⑥ Endinit 복원 */
    IfxScuWdt_setCpuEndinit(endinitPw);

    /* ⑦ 검증 — 기록된 매직넘버를 다시 읽어서 확인 */
    const DrvFlash_CalData *pVerify = (const DrvFlash_CalData *)CAL_FLASH_ADDR;
    if (pVerify->magic != DRVFLASH_CAL_MAGIC)
        return FALSE;

    return TRUE;
}

Write가 끝나면 해당 주소를 다시 읽어서 매직넘버가 정상적으로 기록되었는지 검증합니다. 하드웨어 오류나 전원 불안정으로 Write가 실패할 수 있기 때문입니다.

Write 시퀀스 흐름도

  데이터 준비 (구조체 → wordL, wordU)
       │
  Endinit 해제
       │
  IfxFlash_clearStatus ─────── 이전 에러 플래그 초기화
       │
  IfxFlash_eraseSector ─────── Sector 0 전체(8KB) Erase
       │
  IfxFlash_waitUnbusy ──────── Erase 완료 대기
       │
  IfxFlash_enterPageMode ───── Page Programming 모드 진입
       │

       │
  IfxFlash_writePage ──────── Buffer → Flash 셀 기록
       │
  IfxFlash_waitUnbusy ──────── Write 완료 대기
       │
  Endinit 복원

Flash Read — DrvFlash_LoadCalibration 코드 분석

DFLASH는 메모리 맵 I/O입니다. CPU 주소 공간에 직접 매핑되어 있으므로, 특별한 Flash 명령 없이 포인터로 읽으면 됩니다. 

boolean DrvFlash_LoadCalibration(void)
{
    /* DFLASH 주소를 직접 읽기 (메모리 맵) */
    const DrvFlash_CalData *pFlash = (const DrvFlash_CalData *)CAL_FLASH_ADDR;

    /* 매직넘버로 유효성 검증 */
    if (pFlash->magic != DRVFLASH_CAL_MAGIC)
    {
        return FALSE;   /* Flash에 유효한 데이터 없음 → 기본값 유지 */
    }

    /* Flash → RAM 복원 */
    if (pFlash->pwmDuty <= 100u)
    {
        g_pwmDuty = pFlash->pwmDuty;
    }

    return TRUE;
}

로직은 단순합니다. 0xAF000000을 구조체 포인터로 캐스팅하여 읽고, magic 값이 0xCAFE1234이면 유효한 데이터로 판단합니다. pwmDuty의 범위 검증(0~100)도 추가하여, Flash 데이터가 손상된 경우에도 안전하게 동작합니다.

부팅 시 자동 복원 — Cpu0_Main.c

드라이버 초기화가 끝난 후, DrvFlash_LoadCalibration()을 한 번 호출합니다. Flash에 유효한 데이터가 있으면 자동으로 복원되고, 없으면 기본값을 사용합니다. 

void core0_main(void)
{
    /* Driver 초기화 */
    DrvIntc_Init();
    DrvDio_Init();
    DrvAdc_Init();
    DrvPwm_Init();
    ...
    IfxCpu_enableInterrupts();

    /* Flash에서 캘리브레이션 데이터 복원 */
    if (DrvFlash_LoadCalibration())
    {
        DrvUart_SendString("[CAL] Flash data loaded.\r\n");
    }
    else
    {
        DrvUart_SendString("[CAL] No saved data, using defaults.\r\n");
    }

    DrvUart_SendString("=== TC237 Flash Calibration Demo ===\r\n");
    DrvUart_SendString("Commands: D=xx, SAVE, LOAD, CAL?\r\n");

    while (1)
    {
        Scheduler_Run();
    }
}

UART로 부팅 메시지를 출력하여, Flash 복원 성공 여부를 터미널에서 바로 확인할 수 있습니다.

UART 명령 파서 — AppTask.c

UART를 단순 에코가 아니라 명령 채널로 활용합니다. 1ms Task에서 수신 바이트를 버퍼에 축적하고, Enter(CR/LF)가 들어오면 명령을 파싱합니다.

수신 구조

void AppTask_1ms(void)
{
    uint8 rxByte;
    while (DrvUart_ReceiveByte(&rxByte))
    {
        if (rxByte == '\n' || rxByte == '\r')
        {
            if (s_cmdIdx > 0u)
            {
                processCommand();    /* 명령 처리 */
                s_cmdIdx = 0u;       /* 버퍼 초기화 */
            }
        }
        else
        {
            if (s_cmdIdx < (CMD_BUF_SIZE - 1u))
            {
                s_cmdBuf[s_cmdIdx] = rxByte;
                s_cmdIdx++;
            }
        }
    }
}

32바이트 버퍼에 수신 데이터를 쌓다가 줄바꿈 문자가 오면 processCommand()를 호출합니다. 1ms마다 폴링하므로 115200 bps(약 11.5KB/s) 속도에서 바이트 유실 없이 처리할 수 있습니다.

명령 처리

명령파싱 조건동작응답
D=xx 첫 두 글자가 D=, 뒤에 숫자 g_pwmDuty 즉시 변경 (RAM만) [CAL] Duty=75
SAVE 정확히 4글자 SAVE DrvFlash_SaveCalibration() 호출 [CAL] Saved! Duty=75
LOAD 정확히 4글자 LOAD DrvFlash_LoadCalibration() 호출 [CAL] Loaded! Duty=75
CAL? 정확히 4글자 CAL? 현재 Duty 값 조회 [CAL] Duty=75
주의: 대문자만 인식합니다. save, d=75는 [ERR] Unknown으로 처리됩니다. 뒤에 공백이 붙어도(SAVE ) 길이가 맞지 않아 실패합니다.

D=xx 명령의 숫자 파싱은 parseUint8 함수가 처리합니다. ASCII 문자를 한 자리씩 읽으면서 십진수로 변환하고, 100을 초과하면 100으로 클램핑합니다. 

static uint8 parseUint8(const uint8 *str)
{
    uint16 val = 0u;
    while (*str >= '0' && *str <= '9')
    {
        val = val * 10u + (*str - '0');
        str++;
    }
    if (val > 100u) val = 100u;    /* Duty 범위 제한 */
    return (uint8)val;
}

PFLASH 예제와의 비교

인피니언 ILLD FlashDemo 예제에서 PFLASH에 쓸 때와 우리 코드에서 DFLASH에 쓸 때의 차이를 정리합니다.

정리: 캘리브레이션 데이터처럼 소량의 설정값을 저장하는 용도에는 DFLASH가 적합합니다. PFLASH 예제의 PSPR 복사, 함수포인터 패턴, 32바이트 패딩 처리가 모두 불필요해지므로 코드가 훨씬 간결해집니다. iLLD API를 직접 사용하되, 매직넘버 검증과 UART 명령 인터페이스를 조합하면 실용적인 캘리브레이션 시스템을 만들 수 있습니다.
